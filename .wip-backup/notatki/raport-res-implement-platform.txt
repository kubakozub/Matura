BEHAVIOUR A USER CAN NOTICE

1. A font-size or display-size change, folding or unfolding, split screen, a Bluetooth keyboard or a new system language no longer restart the game. The running round continues, a half-typed set stays, the student stays on the same screen. A right-to-left system language mirrors the layout in place.
2. On a phone in the light system theme the clock, battery and navigation buttons are now light on the dark game instead of dark on dark, and the light translucent strip under three-button navigation is gone. On dark-theme phones the system's own contrast strip under three-button navigation is gone too; the game's dark background is behind it.
3. On Android 16 tablets and unfolded foldables the game stays in portrait instead of following the device into the stretched phone layout.
4. Because the app is declared a game, the system may list it under Games in storage settings and vendor game launchers or dashboards may pick it up.
5. Google Play no longer hides the app from devices that do not report portrait support.
6. The speaker button for words from own sets should work on Android 11+ phones where the speech engine was hidden from the app.
7. On Android 7 to 9, a second start from the icon after "Open" in the store or installer shows the game that is already running instead of a second copy on the name screen.
8. After the app is killed in the middle of a save, the latest answer or saved set is there on the next start instead of the previous state.

A WARNING FOR EVERYONE WHO WRITES TESTS

My first two full debug runs failed with 32 and then 21 failures in Compose tests I had not touched (SystemKeyboardTest, TouchTargetAuditTest, VoiceAlwaysAvailableTest, VoiceTestScreenTest, VoiceUczciwoscTest), each waiting 60 s and ending in AppNotIdleException, which turned a 45 second run into more than 20 minutes. The cause was my own new tests. Any test that creates MainActivity with a Robolectric ActivityController leaves work in the main looper, because setContent writes Compose state in onCreate even when no window is attached, and the controller's destroy and close do not drain the looper. Robolectric drops the message after the test, and from then on every later auto-advancing Compose test in the same JVM hangs. The guilty test passes; innocent ones after it fail.

The fix is in /home/user/Matura/.claude/worktrees/zestawy/app/src/test/java/com/matura/app/GlownaPetla.kt: wykonajToCoCzekaWGlownejPetli(), called from @After in the three classes that create MainActivity. I confirmed it separately for each: without the call the next Compose test hangs 60 s and fails, with it everything passes. Tests built on createComposeRule or ActivityScenario are not affected, because ActivityScenario waits for an idle looper itself. If another branch adds a test that builds MainActivity through Robolectric.buildActivity, it needs the same call. For the same reason the two MainActivity tests in app/src/test never attach the window (create, or create, start, resume, but no setup or visible).

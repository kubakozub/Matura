SUMMARY: Three self-contained Compose screens launched from App.kt Screen.Play (lines 225-239) with one signature (set, options, str, playerName, onExit, onFinished, onAttempt). There is no engine class: rules are private functions plus remember-state keyed on a per-run counter (TF `restarts`, MC `runId`, TA `round`); timers are withFrameNanos loops in LaunchedEffects with clamped dt.

TRUE/FALSE: `usable` = rows for which a false proposal exists (fixed-point filter via hasFalseCandidate); buildQuestion draws with replacement, about 50 % true, false proposals screened with Matching.answersForPrompt/acceptedAnswers. 8/6/4 s per question, lives 1..9, a miss or timeout costs a life. Attempts: ROZPOZNANIE; RIGHT→POPRAWNA, WRONG→BLEDNA, TIMEOUT→POKAZANA.

MULTIPLE CHOICE: buildRound asks every playable entry once per pass with 3 distractors whose accepted-answer sets are pairwise disjoint; a Random(0) probe gates NotEnoughEntries. 12/9/6 s per question, reveal 1.7/1.35/1.05 s, endless passes. Attempts: ROZPOZNANIE; timeout→POKAZANA.

TIME ATTACK: buildQuestions shuffles the set once per run (cyclic); the typed answer (GameKeyboard) is checked with isExactMatch against that row's acceptedAnswers; one clock 120/90/60 s, +2 s hit (capped), −3 s miss, −5 s skip. Attempts: PRZYPOMNIENIE; each wrong ENTER→BLEDNA, skip→POKAZANA, clock running out→nothing.

Scoring in all three: 10 × multiplier (streak ≥3 ×2, ≥6 ×3, ≥9 ×5); level = 1 + hits/10 is cosmetic. onFinished(ScoreRecord) fires once per run from a LaunchedEffect when the end state is reached; exiting earlier records no score (attempts are already saved).

Tests: RodzajZadaniaTest pins only the pure proba* mappers, AnswersForPromptTest pins Matching.answersForPrompt, PodgladEkranowTest is a render smoke test. Question generation, scoring, timers and end flows have no tests. The three files are identical to origin/publikacja; origin/master had none of these modes. A Python port of the generators run over all 102 built-in sets found no dropped MC question and no row lost from TF `usable`.

INTEGRATION: COMMON WIRING (App.kt, Screen.Play branch, lines 165-241)
- All three get: set, options = data.options (not opcjeRundy), str, playerName = data.profile.name, onExit = `exit` (178: refresh(); stack = listOf(Screen.Menu)), onFinished = `finish` (205-208: repo.recordGame(record.copy(mode = s.mode), set.id); refresh()), onAttempt = `zapiszProbe` (192-201: repo.recordAttempt, deliberately no refresh). planSesji is null on every path that reaches these modes (App.kt:138).
- Only other call sites: PodgladEkranowTest.kt:192, 203, 214. onAttempt has no default by design, so any new required parameter must be added there too.
- The screens receive no `progress`, `today` or `profile` (only PlayScreen does, App.kt:221-222). App's `data` is not refreshed during a round, so App's data.progress is the pre-round map until finish() runs and the post-round map afterwards. This also holds across in-screen restarts, because every finished run calls finish().
- Order at round end (all three): the end flag is set in a frame-loop coroutine; the next composition already draws the result UI; only then a LaunchedEffect calls onFinished once (guard `reported`, keyed on the run counter); App runs recordGame + refresh; the screen recomposes. For stored sets a new WordSet instance arrives (timesPlayed+1) with the same `entries` list, so remember(set.id, set.entries, …) is not invalidated and run state survives. Anything derived from refreshed App data therefore arrives one recomposition after the result UI first appears.
- onFinished returns Unit: the screen learns nothing back (new best, unlocked achievements, summary). ScoreRecord carries score, level, bestStreak, kills = correct answers, setTitle, playedAt, mode.
- No screen keeps the run's attempts. Each Attempt is built and handed straight to onAttempt: TF settle() 362-365, MC resolve() 415-421, TA zapiszProbe() 212-214 (called at 219, 234, 253). Entries with a blank id produce no Attempt.
- Podsumowanie.rundy(proby, przed, po, zakres, kierunek, dzis) therefore needs:
  - a per-run list filled at those three points, keyed on restarts/runId/round or it leaks into the next run;
  - `przed` snapshotted at run start;
  - `po`: App's data.progress after finish(), or Srs.applyTo folded over `przed` locally;
  - zakres: TF usable.map{id}, MC entries.map{id}, TA questions.map{entryId};
  - kierunek = options.direction (RANDOM is accepted); dzis = Srs.dayOf(now).
  Do not make progress a remember key of run state (see the comment at App.kt:183-186).
- PodsumowanieRundy (ui/PodsumowanieRundy.kt:61) is not used anywhere in main, and no TekstyRundy/TekstyDzialu instance exists outside PodsumowanieTest. The three screens use private t(pl, en, lang) helpers plus a few Str fields; the TF file comment forbids extending Str.

PAUSE, BACK, RECREATION
- None of the three has a pause; PlayScreen pauses on ON_STOP (PlayScreen.kt:719-732). The frame loops freeze while the activity is stopped and continue immediately on return (dt clamp 0.05 s in TF/TA, 0.25 s in MC).
- Back or exit mid-run is onExit with no confirmation and no onFinished: no ScoreRecord, no result UI, hence no summary or reward. Attempts are already persisted.
- All state is plain remember, including MaturaApp's stack (App.kt:63). Process death or an unhandled configuration change (the manifest handles only orientation|screenSize|keyboardHidden|uiMode) drops the run and restarts at Screen.Start. A per-run attempt list in remember dies with it; saved progress does not.
- Timeout attempts are emitted from closures captured when the LaunchedEffect started (TF settle via 403-420, MC resolve via 461-475), not through rememberUpdatedState as in PlayScreen.kt:229. This is harmless today because App's lambda captures only repo and a state holder; a new onAttempt/onFinished that captures per-composition values would be called stale there.

WHAT WILL SHAPE THE SUMMARY
- TF and MC never end for a player who stops making mistakes (finding tf-mc-no-end-exit-drops-score), so a block placed on the game-over branch is unreachable for them.
- TF: a correct "FAŁSZ" promotes the prompt word from box 0 to 1, so nowoPoznane will count words whose translation was never displayed.
- TF/MC timeouts and TA skips are POKAZANA, so they land in doPonowienia/doPoprawki. TA records one BLEDNA per wrong ENTER, so one word can produce several.
- TF draws with replacement (buildQuestion 187-199 only avoids the same prompt twice in a row): 20 questions on a 20-word set cover about 13 distinct words. MC is a bag per pass; TA is a fixed shuffled cycle.
- JESZCZE RAZ on the random mix replays the same 40-word draw (mixSet is not redrawn).
- App.kt:204 recomputes `dzisiaj` on every recomposition of the Play branch despite its comment; this matters once the three screens take `today`.
